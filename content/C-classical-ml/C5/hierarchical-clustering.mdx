**Hierarchical clustering** builds a tree (dendrogram) instead of a flat
partition: at the bottom, every point is its own cluster; at the top, one
giant cluster<FN n="1" />. The choice of **linkage** decides how distances between
clusters are computed and produces very different dendrograms. Reading the
dendrogram exposes structure at multiple scales.

## Agglomerative vs divisive

- **Agglomerative (bottom-up)**: start with $n$ singletons, repeatedly merge
  the two closest clusters until one remains.
- **Divisive (top-down)**: start with one cluster, recursively split. Less
  common in practice (more expensive).

Agglomerative is the default. The merge order is recorded as a tree, and a
flat clustering at any desired number of clusters is obtained by cutting the
tree.

## Four classical linkages

For clusters $A, B$ with pairwise distances $d(a, b)$:

- **Single linkage**: $d(A, B) = \min_{a \in A, b \in B} d(a, b)$.
  Produces "chained" elongated clusters, sensitive to noise bridges.
- **Complete linkage**: $d(A, B) = \max d(a, b)$.
  Produces compact, similarly-sized clusters; sensitive to outliers.
- **Average linkage**: $d(A, B) = \operatorname{avg}\, d(a, b)$.
  Compromise between single and complete.
- **Ward's linkage**: merges the two clusters whose union minimizes the
  increase in within-cluster sum of squares. Tends to produce balanced,
  spherical clusters; the natural choice for Euclidean data<FN n="2" />.

Different linkages can give entirely different clusterings on the same data.
Picking one is a domain decision, not a default.

## Reading the dendrogram

The y-axis of the dendrogram is the merge distance. A horizontal cut at
height $h$ produces a flat clustering with one cluster per branch crossing
the cut.

- **Long vertical edges** correspond to merges across a large distance
  jump: high stability at intermediate cuts.
- **Many short merges** near the bottom mean dense local structure.
- A clear "gap" of vertical space suggests a natural number of clusters
  (cut just below it).

## Cost

Naive agglomerative clustering is $O(n^3)$ in time and $O(n^2)$ in memory
because every pairwise distance is maintained. Approximate variants (BIRCH,
mini-batch) bring this down for large $n$, but hierarchical clustering is
the slowest classical clusterer.

## When to use

- **Need a hierarchy**: phylogenies, taxonomies, document topic trees.
- **Small $n$**: a few hundred to a few thousand points fits easily.
- **Don't know $k$**: the dendrogram suggests good cut points visually.
- **Non-Euclidean distances**: works with any distance, like k-medoids but
  produces a tree.

## Check it on arrays

```python
import numpy as np

rng = np.random.default_rng(0)

# Three Gaussian blobs
X = np.vstack([
    rng.normal(loc=[2.0, 0.0], scale=0.4, size=(20, 2)),
    rng.normal(loc=[-2.0, 0.0], scale=0.4, size=(20, 2)),
    rng.normal(loc=[0.0, 2.0], scale=0.4, size=(20, 2)),
])

def agglomerative(X, linkage="single"):
    n = len(X)
    D = np.linalg.norm(X[:, None] - X[None, :], axis=2)
    clusters = [{i} for i in range(n)]
    merges = []                                        # (a, b, merge_distance, new_size)
    sizes = [1] * n
    active = list(range(n))
    while len(active) > 1:
        # find the closest pair among active clusters
        best = (None, None, float("inf"))
        for ai in active:
            for bi in active:
                if ai >= bi: continue
                d = D[ai, bi]
                if d < best[2]: best = (ai, bi, d)
        a, b, dist = best
        merges.append((a, b, dist, sizes[a] + sizes[b]))
        clusters[a] = clusters[a] | clusters[b]
        for c in active:
            if c == a or c == b: continue
            if linkage == "single":
                new_d = min(D[a, c], D[b, c])
            elif linkage == "complete":
                new_d = max(D[a, c], D[b, c])
            elif linkage == "average":
                new_d = (sizes[a] * D[a, c] + sizes[b] * D[b, c]) / (sizes[a] + sizes[b])
            elif linkage == "ward":
                new_d = ((sizes[a] + sizes[c]) * D[a, c]**2
                         + (sizes[b] + sizes[c]) * D[b, c]**2
                         - sizes[c] * dist**2) / (sizes[a] + sizes[b] + sizes[c])
                new_d = np.sqrt(max(new_d, 0))
            D[a, c] = D[c, a] = new_d
        sizes[a] = sizes[a] + sizes[b]
        active.remove(b)
    return merges

# Compare linkages
for link in ["single", "complete", "average", "ward"]:
    merges = agglomerative(X.copy(), linkage=link)
    # Distance of the last few merges (top of dendrogram)
    top = [m[2] for m in merges[-5:]]
    print(f"{link:>10} linkage, last 5 merge distances: {[round(d, 2) for d in top]}")

# Cut to produce 3 clusters with single linkage
merges = agglomerative(X.copy(), linkage="ward")
# Walk through merges, stop when 3 clusters remain
n = len(X)
parent = list(range(n))
def find(x):
    while parent[x] != x: parent[x] = parent[parent[x]]; x = parent[x]
    return x
for a, b, dist, _ in merges:
    if len(set(find(i) for i in range(n))) == 3: break
    parent[find(b)] = find(a)
labels = np.array([find(i) for i in range(n)])
_, labels = np.unique(labels, return_inverse=True)
print(f"\nWard cut to 3 clusters: cluster sizes = {[int((labels == c).sum()) for c in set(labels)]}")
```

Each linkage produces a different set of merge distances. Cutting Ward's
dendrogram at 3 clusters recovers the three blobs.

## Exercises

**Exercise 1.** Four points sit on a line at $0, 1, 5, 6$. Build the
agglomerative dendrogram under single linkage by hand: list the merges in order
with their merge distances.

<details>
<summary>Solution</summary>

**Step 1.** Start with four singletons. Pairwise distances are $d(0,1) = 1$,
$d(5,6) = 1$, $d(1,5) = 4$, and larger for the rest. The two closest pairs both
have distance $1$.

**Step 2.** Merge $\{0\}$ and $\{1\}$ at distance $1$ (ties broken arbitrarily;
take this pair first). Then merge $\{5\}$ and $\{6\}$ at distance $1$. Two
clusters remain: $\{0, 1\}$ and $\{5, 6\}$.

**Step 3.** Under single linkage, the distance between the two clusters is the
minimum cross distance, $\min(d(1,5), d(0,5), d(1,6), d(0,6)) = d(1,5) = 4$.
Merge them at distance $4$. The merge sequence is: $\{0,1\}$ at $1$, $\{5,6\}$ at
$1$, then $\{0,1,5,6\}$ at $4$. The jump from $1$ to $4$ is the large vertical
gap that suggests cutting into two clusters.

</details>

**Exercise 2.** Show that single linkage and complete linkage give the same
first merge on any dataset, then give a small example where their second merge
differs.

<details>
<summary>Solution</summary>

**Step 1.** At the start every cluster is a singleton, so for any pair the set of
cross distances has a single element, $d(a, b)$. Both $\min$ and $\max$ over a
one-element set return that element, so single and complete linkage both merge
the globally closest pair first. The first merge is identical.

**Step 2.** Take points on a line at $0, 1, 3$. First merge: $\{0\}$ and $\{1\}$
at distance $1$ under both. Now compare cluster $\{0, 1\}$ to $\{3\}$. Single
linkage uses $\min(d(1,3), d(0,3)) = \min(2, 3) = 2$. Complete linkage uses
$\max(2, 3) = 3$. The recorded merge distance differs ($2$ versus $3$), even
though the merge partners are the same here; on larger sets the differing
distances can change which pair merges next.

</details>

**Exercise 3 (code).** Implement single-linkage agglomerative clustering and
verify on the four-point set $\{0, 1, 5, 6\}$ that the final merge distance is
$4$, matching Exercise 1.

<details>
<summary>Solution</summary>

```python
import numpy as np

X = np.array([[0.0], [1.0], [5.0], [6.0]])

def single_linkage(X):
    n = len(X)
    D = np.linalg.norm(X[:, None] - X[None, :], axis=2)
    active = list(range(n))
    merges = []
    while len(active) > 1:
        best = (None, None, np.inf)
        for ai in active:
            for bi in active:
                if ai < bi and D[ai, bi] < best[2]:
                    best = (ai, bi, D[ai, bi])
        a, b, dist = best
        merges.append(dist)
        for c in active:
            if c not in (a, b):
                D[a, c] = D[c, a] = min(D[a, c], D[b, c])   # single linkage
        active.remove(b)
    return merges

merges = single_linkage(X)
assert np.isclose(merges[0], 1.0)
assert np.isclose(merges[-1], 4.0)                 # final merge distance
print("merge distances:", [round(m, 1) for m in merges])
```

The first two merges happen at distance $1$ and the final merge at distance $4$,
reproducing the dendrogram derived by hand.
