The [log](K4/log-and-kafka) hands you an *unbounded* sequence: events keep arriving
and the stream never ends. Yet every useful metric ("requests per minute",
"average session length") is an aggregate, and an aggregate needs a finite set to
sum over. You cannot wait for the stream to finish, because it never does. The
resolution is to cut the timeline into finite chunks and aggregate within each
chunk. A chunk is a **window**, and the three standard shapes (tumbling, sliding,
session) differ only in how their boundaries are placed<FN n="1" />. The shape you pick changes
the answer, so it is worth defining each precisely.

Throughout, an event carries a timestamp $t$, and a window is a half-open interval
$[a, b)$ on the time axis: an event belongs to it when $a \le t < b$. Half-open so
that an event exactly on a boundary lands in one window, not two.

## Tumbling windows

A **tumbling window** of width $w$ tiles the time axis with fixed, non-overlapping,
gap-free intervals:

$$
W_k = [\,k w,\ (k+1) w\,), \qquad k = 0, 1, 2, \dots
$$

Each event falls into exactly one window, the one with index

$$
k = \left\lfloor \frac{t}{w} \right\rfloor,
$$

where $\lfloor \cdot \rfloor$ is the floor (round down). Because the windows
partition the axis, with no overlap and no gap, the windows form a **partition** of
the events: every event is counted once and only once. That gives the defining
invariant: the per-window counts sum to the total number of events. "Requests per
5-minute bucket" is a tumbling aggregate.

## Sliding windows

A **sliding window** keeps a fixed width $w$ but advances its start by a **slide**
$s < w$ rather than by the full width:

$$
W_k = [\,k s,\ k s + w\,), \qquad k = 0, 1, 2, \dots
$$

Because $s < w$, consecutive windows overlap by $w - s$, so an event near a boundary
is counted in **several** windows at once. This is what you want for a *rolling*
metric: "average over the last 5 minutes, recomputed every 1 minute" is a sliding
window with $w = 5$, $s = 1$. The trade is that the counts no longer sum to the
total; an event in the overlap is counted once per window it touches, so
$\sum_k |W_k| \ge N$. Setting $s = w$ recovers the tumbling case as the boundary
between the two.

## Session windows

Tumbling and sliding windows are *fixed* in placement: their boundaries are decided
by the clock, independent of the data. A **session window** is **data-driven**.
Sort the events by time and walk them in order; a session continues while
consecutive events are close, and a new session begins whenever the gap between two
consecutive events exceeds a threshold $g$:

$$
\text{new session at } t_{i+1} \iff t_{i+1} - t_i > g.
$$

This models bursts of activity separated by idle periods (a user clicking around,
then leaving)<FN n="2" />. The boundary count follows directly from the rule: with $N$ sorted
events there are $N-1$ consecutive gaps, and each gap that exceeds $g$ starts one
new session. So if $m$ of the gaps exceed $g$, the stream splits into

$$
\#\text{sessions} = m + 1
$$

sessions (the first session needs no preceding gap, hence the $+1$). The window
widths are whatever the data make them.

## Worked example

Take twelve event timestamps and assign them to tumbling windows (width 5), to
sliding windows (width 5, slide 2.5), and segment them into sessions (gap threshold
3). The two invariants from above are checked at the end: tumbling counts sum to the
event total, and the session count equals (gaps over threshold) $+ 1$.

```python
import numpy as np

events = np.array([0.5, 1.2, 2.0, 3.7, 6.1, 6.4, 9.9, 10.2, 13.0, 18.5, 18.9, 19.4])
events = np.sort(events)
N = events.size

# --- Tumbling: width 5, non-overlapping. Each event -> floor(t / w). ---
w = 5.0
idx = np.floor(events / w).astype(int)
n_windows = idx.max() + 1
tumbling = np.array([np.sum(idx == k) for k in range(n_windows)])
print("tumbling counts :", tumbling.tolist())

# --- Sliding: width 5, slide 2.5, overlapping. Count per window start. ---
w, s = 5.0, 2.5
starts = np.arange(0.0, events.max() - w + 1e-9, s)
sliding = np.array([np.sum((events >= a) & (events < a + w)) for a in starts])
print("sliding counts  :", sliding.tolist())

# --- Sessions: new session whenever a consecutive gap exceeds g. ---
g = 3.0
gaps = np.diff(events)                 # the N-1 consecutive gaps
m = int(np.sum(gaps > g))             # gaps exceeding the threshold
n_sessions = m + 1
print("gaps over g     :", m, "-> sessions:", n_sessions)

# Invariant 1: tumbling windows partition the events, so counts sum to N.
assert tumbling.sum() == N
# Sliding overlaps, so it counts at least as many (strictly more here).
assert sliding.sum() >= N
# Invariant 2: number of sessions = (gaps over threshold) + 1.
assert n_sessions == m + 1
print("tumbling sum =", int(tumbling.sum()), "= N =", N, "| sessions =", n_sessions)
```

The tumbling counts `[4, 3, 2, 3]` sum to the twelve events, the sliding counts sum
higher because the overlap double-counts boundary events, and the two gaps over
$g=3$ split the stream into three sessions.

## Exercises

**Exercise 1.** Six events have timestamps $t = 1, 4, 7, 9, 14, 16$. Assign each to
a tumbling window of width $w = 5$ using $k = \lfloor t / w \rfloor$, list the
per-window counts, and verify the partition invariant (counts sum to the event
total).

<details>
<summary>Solution</summary>

**Step 1.** Compute the window index $k = \lfloor t / 5 \rfloor$ for each event.
$\lfloor 1/5 \rfloor = 0$, $\lfloor 4/5 \rfloor = 0$, $\lfloor 7/5 \rfloor = 1$,
$\lfloor 9/5 \rfloor = 1$, $\lfloor 14/5 \rfloor = 2$, $\lfloor 16/5 \rfloor = 3$.

**Step 2.** Tally per window: window 0 $= [0, 5)$ holds $\{1, 4\}$, count 2; window
1 $= [5, 10)$ holds $\{7, 9\}$, count 2; window 2 $= [10, 15)$ holds $\{14\}$,
count 1; window 3 $= [15, 20)$ holds $\{16\}$, count 1. Counts are $[2, 2, 1, 1]$.

**Step 3.** Invariant check. Tumbling windows tile the axis with no overlap and no
gap, so every event lands in exactly one window. The counts sum to
$2 + 2 + 1 + 1 = 6$, equal to the six events. The partition invariant holds.

</details>

**Exercise 2.** Take the same events $t = 1, 4, 7, 9, 14, 16$. Apply a sliding
window of width $w = 5$ and slide $s = 2$, with starts $0, 2, 4, \dots$ up to the
last start that still admits an event. Show that the per-window counts sum to *more*
than 6, and identify which event is counted in the most windows and why.

<details>
<summary>Solution</summary>

**Step 1.** Windows are $[ks, ks + 5)$ for $k = 0, 1, 2, \dots$, i.e. starts
$0, 2, 4, 6, 8, 10, 12, 14, 16$. An event $t$ is in window $[a, a+5)$ when
$a \le t < a + 5$.

**Step 2.** Count each event's window memberships (number of starts $a$ with
$a \le t < a + 5$, i.e. $t - 5 < a \le t$ among the valid starts):
- $t = 1$: starts in $(-4, 1] \to \{0\}$, so 1 window.
- $t = 4$: starts in $(-1, 4] \to \{0, 2, 4\}$, so 3 windows.
- $t = 7$: starts in $(2, 7] \to \{4, 6\}$, so 2 windows.
- $t = 9$: starts in $(4, 9] \to \{6, 8\}$, so 2 windows.
- $t = 14$: starts in $(9, 14] \to \{10, 12, 14\}$, so 3 windows.
- $t = 16$: starts in $(11, 16] \to \{12, 14, 16\}$, so 3 windows.

**Step 3.** Total memberships $= 1 + 3 + 2 + 2 + 3 + 3 = 14 > 6$. Because $s < w$,
consecutive windows overlap by $w - s = 3$, so events away from the very start are
counted several times; the sum exceeds $N$ exactly by the overlap double-counting.

**Step 4.** The events counted in the most windows are $t = 4, 14, 16$, each in 3.
An interior event sits inside the full overlap region, so the maximum number of
windows of width 5 stepping by 2 that can cover one point is
$\lceil w / s \rceil = \lceil 5/2 \rceil = 3$. Events near the start of the axis
($t = 1$) fall in fewer because no windows begin before 0.

</details>

**Exercise 3 (code).** Implement all three window assignments directly in numpy and
stdlib: tumbling ($w = 4$), sliding ($w = 4$, $s = 2$), and session segmentation
(gap threshold $g = 2$). Use the timestamps below. Assert the tumbling counts sum to
$N$, the sliding counts sum to strictly more than $N$, and the session count equals
(gaps over threshold) $+ 1$.

<details>
<summary>Solution</summary>

```python
import numpy as np

events = np.sort(np.array(
    [0.4, 1.1, 1.9, 3.5, 3.8, 8.2, 8.5, 9.0, 13.7, 14.1, 14.6, 19.2]))
N = events.size

# --- Tumbling: width 4, non-overlapping. Each event -> floor(t / w). ---
w = 4.0
idx = np.floor(events / w).astype(int)
n_win = idx.max() + 1
tumbling = np.array([int(np.sum(idx == k)) for k in range(n_win)])
print("tumbling counts :", tumbling.tolist())

# --- Sliding: width 4, slide 2, overlapping. Count per window start. ---
w, s = 4.0, 2.0
starts = np.arange(0.0, events.max() - w + 1e-9, s)
sliding = np.array([int(np.sum((events >= a) & (events < a + w))) for a in starts])
print("sliding counts  :", sliding.tolist())

# --- Sessions: new session whenever a consecutive gap exceeds g. ---
g = 2.0
gaps = np.diff(events)                 # the N-1 consecutive gaps
m = int(np.sum(gaps > g))             # gaps exceeding the threshold
n_sessions = m + 1
print("gaps over g     :", m, "-> sessions:", n_sessions)

# Tumbling partitions the events, so counts sum to N.
assert tumbling.sum() == N
# Sliding overlaps (s < w), so it counts strictly more than N here.
assert sliding.sum() > N
# Sessions = (gaps over threshold) + 1.
assert n_sessions == m + 1
print("tumbling sum =", int(tumbling.sum()), "= N =", N, "| sessions =", n_sessions)
```

Tumbling counts sum to $N$ because each event lands in exactly one window; sliding
counts exceed $N$ because the width-4 step-2 overlap double-counts boundary events;
and the gaps wider than 2 split the stream into the asserted number of sessions. The
window shape, not the data, decides whether an event is counted once or many times.

</details>

Every window above is keyed off the
event's *own* timestamp $t$, which quietly assumed events arrive in timestamp
order. They do not, and the [next lesson](K4/watermarks-late-data) confronts what
happens when an event for an already-closed window shows up late.
