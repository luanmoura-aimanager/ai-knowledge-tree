A pipeline that runs to completion has not necessarily produced *good* data. The
job succeeded, rows landed in the warehouse, and yet a quarter of the email
addresses are null, a price column holds a few negative numbers, and one customer
id appears twice. "Quality" is too vague to act on until it is split into
**dimensions**, each a property you can compute a number for. Once every
dimension is a number, a check is a comparison against a threshold, and a
threshold is something you can alert on. This lesson defines four load-bearing
dimensions and turns each into an automated check with a pass rate<FN n="1" />.

## The four dimensions

The choice of dimensions is not arbitrary: completeness, validity, consistency, and
the rest trace back to empirical work on what data consumers actually mean by
"quality"<FN n="2" />. Each dimension below is defined as a **pass rate**: the fraction
of rows (or of the relevant pairs) that satisfy a rule. A pass rate lives in $[0, 1]$, so the
same alert logic, "page when the rate drops below $\tau$", applies to all of them.

**Completeness** asks whether required values are present. For a column with $N$
rows of which $m$ are null, the completeness rate is the non-null fraction:

$$
c = \frac{N - m}{N} = 1 - \frac{m}{N}.
$$

If you injected exactly $m$ nulls into a clean column, $c$ recovers $1 - m/N$ by
construction; that identity is what the worked block checks.

**Validity** asks whether present values fall in their allowed set: a range
(`age` in $[0, 120]$), a format (an email matching a pattern), or an enumeration.
For a column of $N$ values of which $k$ violate the rule, the validity rate is

$$
v = \frac{N - k}{N}.
$$

Validity is evaluated only on the present values; a null is an absence, scored by
completeness, not a wrong value.

**Uniqueness** asks whether a key column has no duplicates. With $N$ rows and $u$
distinct key values, the duplicate count is $N - u$ and the uniqueness rate is

$$
q = \frac{u}{N}.
$$

A perfect key has $u = N$ and $q = 1$; every repeated id pulls $u$ below $N$.

**Consistency** asks whether values agree across columns or across tables: a
cross-field rule (`ship_date` $\ge$ `order_date`) or a foreign-key rule (every
`customer_id` in `orders` exists in `customers`). It is a pass rate over the
*pairs* or *references* checked, $(\text{satisfying}) / (\text{total})$, so it
slots into the same alert.

## From a dimension to an alert

A **check** is a dimension's rate plus a threshold $\tau$ and a verdict:

$$
\text{pass} \iff \text{rate} \ge \tau .
$$

The threshold is a policy choice. A primary-key uniqueness check is usually
$\tau = 1.0$ (any duplicate is a defect); a completeness check on an
optional-but-expected field might sit at $\tau = 0.95$. Running every check on
each load gives a vector of pass rates; the load is healthy when all of them
clear their thresholds, and the first to drop tells you which dimension broke.
This is the same "compute a number, compare to a threshold" shape as
[transformation tests](K5/transformation-as-code), now pointed at the data rather
than the code.

## Worked example

Build a small table as numpy arrays, inject a *known* number of defects into each
dimension, then compute the four rates and confirm they match the injected defect
rates exactly. The final check shows a sub-threshold rate failing.

```python
import numpy as np
rng = np.random.default_rng(0)

N = 1000

# completeness: inject exactly m nulls (NaN) into an otherwise full column
m = 80
amount = rng.normal(50.0, 10.0, size=N)
null_idx = rng.choice(N, size=m, replace=False)
amount[null_idx] = np.nan

# validity: a price column where exactly k values are out of range (negative)
k = 30
price = rng.uniform(1.0, 99.0, size=N)
bad_idx = rng.choice(N, size=k, replace=False)
price[bad_idx] = -1.0

# uniqueness: a key column with exactly d duplicate rows (d distinct ids reused)
d = 12
key = np.arange(N)
key[-d:] = key[:d]                      # last d rows duplicate the first d ids

def completeness(col):
    return np.mean(~np.isnan(col))

def validity(col, lo, hi):
    present = col[~np.isnan(col)]
    return np.mean((present >= lo) & (present <= hi))

def uniqueness(col):
    return np.unique(col).size / col.size

c = completeness(amount)
v = validity(price, 0.0, 100.0)
q = uniqueness(key)

print(f"completeness = {c:.3f}  (expect {1 - m/N:.3f})")
print(f"validity     = {v:.3f}  (expect {(N - k)/N:.3f})")
print(f"uniqueness   = {q:.3f}  (expect {(N - d)/N:.3f})")

# rates match the injected defect rates exactly
assert np.isclose(c, 1 - m / N)
assert np.isclose(v, (N - k) / N)
assert np.isclose(q, (N - d) / N)

# a check is a rate-vs-threshold verdict; uniqueness here fails tau = 1.0
tau = 1.0
passed = q >= tau
print(f"uniqueness check at tau={tau}: {'pass' if passed else 'FAIL'}")
assert passed is False
```

The four rates land on $1 - m/N$, $(N-k)/N$, and $(N-d)/N$ to the digit, which is
why a quality report is auditable: each number is a defect count divided by a row
count, nothing hidden.

## Exercises

**Exercise 1.** A column has $N = 200$ rows. Of these, 30 are null. Of the 170
present values, 8 fall outside the allowed range. Compute the completeness rate and
the validity rate by hand, and explain why the validity denominator is 170 and not
200.

<details>
<summary>Solution</summary>

**Step 1.** Completeness is the non-null fraction:
$c = (N - m)/N = (200 - 30)/200 = 170/200 = 0.85$.

**Step 2.** Validity is scored only on present values: of the $N - m = 170$
present values, $k = 8$ violate the range, so $v = (170 - 8)/170 = 162/170 \approx 0.953$.

**Step 3.** A null is an *absence*, already penalized by completeness. Counting it
again as a validity failure would double-count the same defect, and a null has no
value to test against the range rule. So validity divides by the 170 present
values, not the full 200. The two dimensions measure disjoint kinds of defect:
missing versus wrong.

</details>

**Exercise 2.** A primary-key uniqueness check uses threshold $\tau = 1.0$. A
table of $N = 500$ rows has $u = 497$ distinct key values. Compute the uniqueness
rate, state the verdict, and explain why $\tau = 1.0$ is the natural threshold for
a primary key while a completeness check on an optional field might use
$\tau = 0.95$.

<details>
<summary>Solution</summary>

**Step 1.** The uniqueness rate is $q = u/N = 497/500 = 0.994$. The duplicate
count is $N - u = 3$.

**Step 2.** The verdict is $\text{pass} \iff q \ge \tau$. Here
$0.994 \ge 1.0$ is false, so the check **fails**.

**Step 3.** A primary key must identify a row uniquely; a single duplicate already
breaks that guarantee and corrupts any join on the key, so any defect is
intolerable and $\tau = 1.0$. An optional-but-expected field tolerates a small
fraction of missing values without breaking downstream use, so its threshold is set
below 1 (e.g. 0.95) to alert only when nulls become unusually common rather than on
every absent value. The threshold encodes how costly a defect in that dimension is.

</details>

**Exercise 3 (code).** Build a 500-row table as numpy arrays. Inject exactly 50
nulls into one column, exactly 20 out-of-range values into a second, and exactly 7
duplicate keys into a third. Compute completeness, validity, and uniqueness, and
assert each rate matches its injected defect rate exactly.

<details>
<summary>Solution</summary>

```python
import numpy as np
rng = np.random.default_rng(0)

N = 500

# completeness: inject exactly m nulls
m = 50
amount = rng.normal(50.0, 10.0, size=N)
amount[rng.choice(N, size=m, replace=False)] = np.nan

# validity: exactly k out-of-range (negative) prices
k = 20
price = rng.uniform(1.0, 99.0, size=N)
price[rng.choice(N, size=k, replace=False)] = -1.0

# uniqueness: exactly d duplicate keys (reuse the first d ids in the last d rows)
d = 7
key = np.arange(N)
key[-d:] = key[:d]

def completeness(col):
    return np.mean(~np.isnan(col))

def validity(col, lo, hi):
    present = col[~np.isnan(col)]
    return np.mean((present >= lo) & (present <= hi))

def uniqueness(col):
    return np.unique(col).size / col.size

c = completeness(amount)
v = validity(price, 0.0, 100.0)
q = uniqueness(key)

print(f"completeness = {c:.3f}  (expect {1 - m/N:.3f})")
print(f"validity     = {v:.3f}  (expect {(N - k)/N:.3f})")
print(f"uniqueness   = {q:.3f}  (expect {(N - d)/N:.3f})")

assert np.isclose(c, 1 - m / N)
assert np.isclose(v, (N - k) / N)
assert np.isclose(q, (N - d) / N)
```

Each rate is a defect count divided by the row count, so completeness recovers
$1 - 50/500 = 0.90$, validity recovers $480/500 = 0.96$, and uniqueness recovers
$493/500 = 0.986$, matching the injected defects to the digit.

</details>
