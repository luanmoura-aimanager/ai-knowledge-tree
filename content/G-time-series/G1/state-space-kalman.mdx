ARIMA and ETS look like different recipes, but both are instances of one object: a
linear-Gaussian **state-space model**. Casting them this way gives a single engine,
the Kalman filter, that evaluates the exact likelihood, handles missing data, and
produces prediction intervals<FN n="1" />. This lesson connects the filter you derived for
graphical models to time-series estimation.

## The state-space template

A linear-Gaussian state-space model has a hidden state $z_t$ that evolves linearly
and an observation $x_t$ that reads a linear function of it, both with Gaussian
noise:

$$
z_t = F z_{t-1} + w_t, \quad w_t \sim \mathcal{N}(0, Q),
$$
$$
x_t = H z_t + v_t, \quad v_t \sim \mathcal{N}(0, R).
$$

$F$ is the transition matrix, $H$ the observation matrix, $Q$ and $R$ the process
and measurement noise covariances. The Kalman-filter lesson derived the predict
and update recursions for this exact template; here the task is to choose $F$, $H$,
$Q$, $R$ so the model *is* an ARIMA or an ETS.

## Putting AR(p) in state-space form

Take an AR(2): $x_t = \phi_1 x_{t-1} + \phi_2 x_{t-2} + \varepsilon_t$. Stack the
last two values into the state $z_t = (x_t,\, x_{t-1})^\top$. Then

$$
z_t = \underbrace{\begin{pmatrix} \phi_1 & \phi_2 \\ 1 & 0 \end{pmatrix}}_{F} z_{t-1} + \begin{pmatrix} \varepsilon_t \\ 0 \end{pmatrix}, \qquad x_t = \underbrace{\begin{pmatrix} 1 & 0 \end{pmatrix}}_{H} z_t.
$$

The top row of $F$ is the AR recursion; the bottom row shifts the old value down.
The process noise enters only the first component, so
$Q = \operatorname{diag}(\sigma^2, 0)$, and the observation is noiseless,
$R = 0$, since $x_t$ is the first state exactly. MA terms and differencing extend
the state vector the same way; this companion-form construction handles any ARIMA.

ETS models fit the template too: the level, trend, and seasonal indices become the
state, and their update equations become $F$. The single error per ETS equation
maps to a one-dimensional $w_t$.

## The likelihood from the filter

The reason to do all this: the Kalman filter hands you the exact Gaussian
likelihood for free. As it sweeps forward, the predict step produces a one-step
forecast of the observation,

$$
\hat{x}_{t \mid t-1} = H F \mu_{t-1}, \qquad S_t = H \hat{\Sigma}_t H^\top + R,
$$

with $\mu_{t-1}$ the filtered state mean and $\hat{\Sigma}_t$ the predicted state
covariance. The **innovation** is the forecast error
$e_t = x_t - \hat{x}_{t \mid t-1}$, and under the model $e_t \sim \mathcal{N}(0, S_t)$,
independent across $t$.

**Prediction-error decomposition.**<FN n="2" /> Because the innovations are independent
Gaussians, the joint log-likelihood factorizes into a sum:

$$
\ln L(\theta) = -\frac{1}{2} \sum_{t=1}^{n} \left[ \ln(2\pi S_t) + \frac{e_t^2}{S_t} \right].
$$

This is the engine behind ARIMA and ETS fitting: run the filter for a candidate
parameter set $\theta = (\phi, \theta, \sigma^2, \dots)$, read off $e_t$ and $S_t$,
sum the formula, and hand the negative of it to a numerical optimizer. Missing
observations are handled by skipping the update step on those dates, which no
ad-hoc imputation can match for correctness.

## Filtering, prediction, smoothing

The same machinery answers three questions with different conditioning sets:

- **Filtering** estimates $z_t$ from data up to $t$. This is the forward pass.
- **Prediction** runs the transition without an update to forecast beyond the data.
- **Smoothing** estimates $z_t$ from the *whole* series with a backward pass, used
  for retrospective decomposition into level, trend, and seasonal parts.

```python
import numpy as np

rng = np.random.default_rng(2)

# Generate AR(2), then recover the Gaussian log-likelihood via the Kalman filter
phi1, phi2, sig2 = 0.5, 0.3, 1.0
n = 800
x = np.zeros(n)
for t in range(2, n):
    x[t] = phi1*x[t-1] + phi2*x[t-2] + rng.normal(0, np.sqrt(sig2))

def kalman_loglik(x, phi1, phi2, sig2):
    F = np.array([[phi1, phi2], [1.0, 0.0]])
    H = np.array([[1.0, 0.0]])
    Q = np.array([[sig2, 0.0], [0.0, 0.0]])
    mu = np.zeros(2); P = np.eye(2) * 10.0      # diffuse prior
    ll = 0.0
    for xt in x:
        mu = F @ mu; P = F @ P @ F.T + Q         # predict
        e  = xt - (H @ mu)[0]                     # innovation
        S  = (H @ P @ H.T)[0, 0]                  # innovation variance
        ll += -0.5*(np.log(2*np.pi*S) + e*e/S)
        K  = (P @ H.T) / S                        # update
        mu = mu + (K[:, 0] * e)
        P  = P - K @ H @ P
    return ll

# Likelihood peaks near the true parameters
ll_true  = kalman_loglik(x, 0.5, 0.3, 1.0)
ll_wrong = kalman_loglik(x, 0.1, 0.1, 1.0)
print(f"log-lik at true params:  {ll_true:.1f}")
print(f"log-lik at wrong params: {ll_wrong:.1f}  (lower, as expected)")
```

The filter assigns a higher log-likelihood to the true coefficients than to wrong
ones, which is exactly the signal an optimizer climbs to estimate ARIMA and ETS
parameters.

## Exercises

**Exercise 1.** Run one Kalman update by hand for a scalar local-level model. The
state is $z_t = z_{t-1} + w_t$ with process variance $Q = 1$, and the observation
is $x_t = z_t + v_t$ with measurement variance $R = 4$. After the predict step you
hold a prior mean $\mu = 10$ and prior variance $P = 5$, and you observe $x = 13$.
Compute the innovation $e$, the innovation variance $S$, the Kalman gain $K$, and
the posterior mean and variance.

<details>
<summary>Solution</summary>

**Step 1.** Form the innovation. The one-step forecast of the observation is
$H\mu = \mu = 10$, so the forecast error is $e = x - \mu = 13 - 10 = 3$.

**Step 2.** Form the innovation variance. With $H = 1$,
$S = P + R = 5 + 4 = 9$.

**Step 3.** Form the Kalman gain $K = P / S = 5 / 9 \approx 0.5556$. The gain sits
between $0$ and $1$: the observation is noisier than the prior, so the update only
partly follows it.

**Step 4.** Update the mean and variance:

$$
\mu^{+} = \mu + K e = 10 + \tfrac{5}{9}\cdot 3 = 10 + \tfrac{5}{3} \approx 11.667,
$$
$$
P^{+} = (1 - K) P = \left(1 - \tfrac{5}{9}\right)\cdot 5 = \tfrac{4}{9}\cdot 5 = \tfrac{20}{9} \approx 2.222.
$$

The posterior variance $20/9$ is below the prior $5$: the measurement tightened the
estimate even though it was noisy.

</details>

**Exercise 2.** In the AR(2) state-space form of this lesson the observation is
noiseless, $R = 0$, and the state's first component equals $x_t$ exactly. Show that
under the diffuse prior this makes the very first innovation variance $S_t$ huge,
and explain why the prediction-error likelihood still behaves once the filter has
seen two observations.

<details>
<summary>Solution</summary>

**Step 1.** With the diffuse prior $P = 10 I$ the predicted state covariance after
the first predict step is $\hat\Sigma_1 = F P F^\top + Q$, whose top-left entry is
on the order of $10$ times the squared AR coefficients plus $\sigma^2$. The
innovation variance is $S_1 = H \hat\Sigma_1 H^\top + R = \hat\Sigma_1[0,0]$, which
is large because the prior is deliberately uninformative.

**Step 2.** A large $S_1$ makes the first term $\ln(2\pi S_1) + e_1^2/S_1$
contribute a large constant offset but a near-zero quadratic penalty, so the first
observation carries almost no information about $\theta$. This is the intended
effect of the diffuse prior: it declines to commit before data arrives.

**Step 3.** Once two observations are in, the noiseless observation $R = 0$ pins the
first state component to the data, so the filtered covariance collapses toward the
true $Q$ structure. From there $S_t$ settles near $\sigma^2$ and each later
innovation $e_t^2 / S_t$ carries genuine information about $\phi_1, \phi_2,
\sigma^2$. The diffuse start contributes a fixed offset that the optimizer ignores
because it does not depend on the parameters being fit at the dominant scale.

</details>

**Exercise 3 (code).** Implement the scalar local-level Kalman filter and confirm
the manual computation of Exercise 1: one update from prior $(\mu, P) = (10, 5)$
with $Q = 1$ already applied to the prior, $R = 4$, and observation $x = 13$ should
give posterior mean $35/3$ and posterior variance $20/9$. Then run the filter over
a simulated local-level series and check that the running posterior variance
converges to a fixed point below the prior.

<details>
<summary>Solution</summary>

```python
import numpy as np

# Single update, matching Exercise 1 (prior already includes the predict step)
mu, P, R, x = 10.0, 5.0, 4.0, 13.0
e = x - mu
S = P + R
K = P / S
mu_post = mu + K * e
P_post = (1 - K) * P
assert np.isclose(mu_post, 35/3)
assert np.isclose(P_post, 20/9)

# Full filter over a simulated local-level series; posterior variance -> fixed point
rng = np.random.default_rng(0)
Q, R = 1.0, 4.0
n = 2000
level = np.cumsum(rng.normal(0, np.sqrt(Q), n))
obs = level + rng.normal(0, np.sqrt(R), n)

mu, P = 0.0, 1e6                 # diffuse prior
P_hist = []
for xt in obs:
    P = P + Q                    # predict
    S = P + R                    # innovation variance
    K = P / S
    mu = mu + K * (xt - mu)      # update
    P = (1 - K) * P
    P_hist.append(P)

P_hist = np.array(P_hist)
P_star = P_hist[-1]
# Fixed point of P+ = (1-K)(P+Q) with K=(P+Q)/(P+Q+R): solve P*^2 + Q P* - Q R = 0
P_fixed = (-Q + np.sqrt(Q**2 + 4*Q*R)) / 2
assert np.isclose(P_star, P_fixed, atol=1e-6)
assert P_star < 1e6              # well below the diffuse prior
print("posterior variance fixed point:", round(P_star, 4))
```

The single update reproduces the by-hand posterior $(35/3, 20/9)$, and the running
posterior variance settles to the steady-state value $P^\star = (-Q + \sqrt{Q^2 +
4QR})/2 \approx 1.562$, the positive root of the algebraic Riccati equation for this
scalar model.

</details>
