A trained model's weights are [floating-point](A/floating-point) numbers, usually
$16$ or $32$ bits each. **Quantization** stores them in fewer bits, typically $8$
or even $4$ integer bits, and that is not just a storage trick. For the
memory-bound decoding that dominates LLM serving, the bottleneck is moving weights
from memory to the compute units, so halving or quartering the bytes per weight is
close to a direct latency win. The price is precision: integers cannot represent
the original values exactly, and the engineering question is how to map floats to
integers so the error stays small and controlled. The standard answer is **affine
quantization**<FN n="1" />.

To make the stakes concrete, weigh a 7-billion-parameter model. Each weight at
fp32 is $4$ bytes, so the raw footprint is $7\times10^9 \times 4 = 28$ GB. The bits
per weight set everything else in proportion:

- **fp32** ($4$ B/weight): $28$ GB. Will not fit on a $24$ GB consumer GPU.
- **fp16** ($2$ B/weight): $14$ GB. The usual serving default.
- **int8** ($1$ B/weight): $7$ GB. Now it fits a single $24$ GB card with room for
  activations.
- **int4** ($\tfrac12$ B/weight): $3.5$ GB. Eight times smaller than fp32, small
  enough for a laptop GPU, and where accuracy starts to need careful schemes.

The footprint scales linearly with the bit budget, so the same map that saves
bytes is the one that decides whether the model fits the hardware at all.

## The affine map

Take a tensor of weights spanning the range $[\beta_{\min}, \beta_{\max}]$, and a
budget of $b$ bits, giving integer codes $q \in \{0, 1, \dots, 2^b - 1\}$. An
affine (linear) map sends a float $x$ to an integer and back. It is fixed by two
numbers:

- the **scale** $s$, the size of one quantization step, chosen so the float range
  spans the whole integer range:
  $$
  s = \frac{\beta_{\max} - \beta_{\min}}{(2^b - 1) - 0} = \frac{\beta_{\max} - \beta_{\min}}{2^b - 1},
  $$
- the **zero-point** $z$, the integer code that represents the float $0$, chosen so
  that $x = \beta_{\min}$ lands on code $0$:
  $$
  z = -\operatorname{round}\!\big(\beta_{\min} / s\big).
  $$

**Quantize** by dividing out the scale, rounding to the nearest integer, shifting
by the zero-point, and clamping into range:

$$
q = \operatorname{clip}\!\Big(\operatorname{round}\!\big(x / s\big) + z,\; 0,\; 2^b - 1\Big).
$$

**Dequantize** by inverting the affine map (the clip and round are not invertible,
which is where the error lives):

$$
\hat{x} = s \,(q - z).
$$

The zero-point matters because real weight distributions are not symmetric about
$0$; an asymmetric range like $[-0.2, 0.8]$ would waste codes if forced to be
symmetric. The affine form spends every code inside the actual range.

## The error is bounded by half a step

How wrong can $\hat{x}$ be? The only lossy operation is the rounding (ignoring
clamped outliers, which sit at the range ends by construction). Rounding $x/s$ to
the nearest integer changes it by at most $\tfrac{1}{2}$:

$$
\big| x/s - \operatorname{round}(x/s) \big| \le \tfrac{1}{2}.
$$

Multiply through by $s$. Since dequantization multiplies the rounded code back by
$s$ and the zero-point cancels (it is added in quantize, subtracted in dequantize),
the reconstruction error is exactly $s$ times the rounding error:

$$
|x - \hat{x}| \le \frac{s}{2}.
$$

So **the worst-case error is half a quantization step**, and the step $s$ shrinks
as the bit budget $b$ grows (more codes across the same range) or as the range
$[\beta_{\min}, \beta_{\max}]$ tightens. This is why **outliers hurt**: one extreme
weight stretches the range, inflating $s$ and therefore the error on *every* weight,
which is the problem the LLM-specific [quantization](E/quantization) schemes
(per-channel scales, outlier handling) are built to solve<FN n="2" />.

## Worked example

We quantize a tensor of weights to $8$-bit integers with the affine map,
dequantize, and confirm both the half-step error bound and the $4\times$ memory
saving over fp32.

```python
import numpy as np
rng = np.random.default_rng(0)

w = rng.normal(0, 0.1, size=10_000).astype(np.float32)   # fp32 weights
bits = 8
qmin, qmax = 0, 2**bits - 1
beta_min, beta_max = float(w.min()), float(w.max())

scale = (beta_max - beta_min) / (qmax - qmin)            # size of one step
zero_point = qmin - round(beta_min / scale)              # integer code for 0.0

# Quantize: scale down, round, shift by zero-point, clamp into [0, 255].
q = np.clip(np.round(w / scale) + zero_point, qmin, qmax).astype(np.uint8)
# Dequantize: invert the affine map (round + clip are where the error entered).
deq = (q.astype(np.float32) - zero_point) * scale

err = np.abs(w - deq)
print(f"scale (one step) = {scale:.2e}")
print(f"max error        = {err.max():.2e}   bound s/2 = {scale/2:.2e}")
print(f"mean error       = {err.mean():.2e}")
assert err.max() <= scale / 2 + 1e-9                     # half-step bound holds
print(f"memory: fp32 {w.nbytes} B -> int8 {q.nbytes} B  ({w.nbytes // q.nbytes}x smaller)")
```

Every reconstructed weight lands within half a step of the original, exactly the
bound, and the tensor shrinks fourfold from fp32 to int8.

## Exercises

**Exercise 1.** A weight tensor spans $[\beta_{\min}, \beta_{\max}] = [-0.3, 0.5]$
and is quantized to $b = 8$ bits. Compute the scale $s$, the zero-point $z$, and the
worst-case reconstruction error $s/2$. Verify that the code for $x = 0$ is exactly
$z$ and lands back on $0$ after dequantization.

<details>
<summary>Solution</summary>

**Step 1.** The integer range is $2^8 - 1 = 255$, so the scale is

$$
s = \frac{0.5 - (-0.3)}{255} = \frac{0.8}{255} \approx 3.137 \times 10^{-3}.
$$

**Step 2.** The zero-point is $z = -\operatorname{round}(\beta_{\min}/s)$:

$$
\beta_{\min}/s = -0.3 / 3.137\times10^{-3} \approx -95.625,
\quad z = -\operatorname{round}(-95.625) = 96.
$$

**Step 3.** The worst-case error is half a step:

$$
s/2 \approx 1.57 \times 10^{-3}.
$$

**Step 4.** Quantizing $x = 0$: $\operatorname{round}(0/s) + z = 0 + 96 = 96 = z$.
Dequantizing: $s(96 - 96) = 0$. The float $0$ maps to code $z$ and back to $0$
exactly, which is why the zero-point is named for it.

</details>

**Exercise 2.** Two tensors share the same true range $[-0.2, 0.2]$, but one has a
single outlier weight at $2.0$ added to it, stretching its range to $[-0.2, 2.0]$.
Both are quantized to $8$ bits. Compute the worst-case error $s/2$ for each and the
ratio between them. Explain in one sentence why outliers hurt every weight.

<details>
<summary>Solution</summary>

**Step 1.** Clean range $0.4$ wide: $s_1 = 0.4 / 255 \approx 1.569 \times 10^{-3}$,
so $s_1/2 \approx 7.84 \times 10^{-4}$.

**Step 2.** Outlier range $2.2$ wide: $s_2 = 2.2 / 255 \approx 8.627 \times 10^{-3}$,
so $s_2/2 \approx 4.31 \times 10^{-3}$.

**Step 3.** The ratio is $s_2 / s_1 = 2.2 / 0.4 = 5.5$.

The outlier widens the range by $5.5\times$, inflating the step and the worst-case
error on every weight by the same factor, because one global scale must cover the
whole range, so a single extreme value spends precision that the bulk of the
weights never use.

</details>

**Exercise 3 (code).** Quantize a tensor of $20{,}000$ fp32 weights drawn from
$\mathcal{N}(0, 0.1)$ to both int8 and int4 with the affine map. Report the
max error and the half-step bound for each, and confirm the int4 step (and so its
error bound) is larger than int8 by the factor $(2^8-1)/(2^4-1) = 17$ given the
same range.

<details>
<summary>Solution</summary>

```python
import numpy as np
rng = np.random.default_rng(0)

w = rng.normal(0, 0.1, size=20_000).astype(np.float32)
beta_min, beta_max = float(w.min()), float(w.max())

def affine_quant(w, bits):
    qmin, qmax = 0, 2**bits - 1
    scale = (beta_max - beta_min) / (qmax - qmin)        # one step
    zero_point = qmin - round(beta_min / scale)          # code for 0.0
    q = np.clip(np.round(w / scale) + zero_point, qmin, qmax)
    deq = (q - zero_point) * scale                       # invert the map
    return scale, np.abs(w - deq).max()

s8, err8 = affine_quant(w, 8)
s4, err4 = affine_quant(w, 4)
print(f"int8: step {s8:.2e}, max err {err8:.2e}, bound {s8/2:.2e}")
print(f"int4: step {s4:.2e}, max err {err4:.2e}, bound {s4/2:.2e}")
print(f"step ratio int4/int8 = {s4/s8:.2f}")

assert err8 <= s8 / 2 + 1e-9                  # half-step bound holds at 8 bits
assert err4 <= s4 / 2 + 1e-9                  # and at 4 bits
assert np.isclose(s4 / s8, (2**8 - 1) / (2**4 - 1), rtol=1e-6)   # 255/15 = 17
```

The same range split into $15$ codes (int4) instead of $255$ (int8) makes each step
$255/15 = 17$ times larger, so dropping four bits multiplies the worst-case error by
$17$, the concrete cost of the smaller bit budget.

</details>
