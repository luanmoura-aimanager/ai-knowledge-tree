Random search pays full price for every configuration it tries, even the hopeless
ones. But you usually do not need a full training run to tell that a configuration
is bad: a learning rate that diverges, or a model that is still near chance after
a fraction of an epoch, has already announced itself. **Multi-fidelity HPO**
exploits this. It treats training budget as a dial, evaluates many configurations
*cheaply* first, and spends real budget only on the ones that survive. The core
rule is **successive halving**.

## Fidelity as a budget dial

A **fidelity** is a cheap, partial evaluation of a configuration: train for a few
epochs instead of all of them, on a subset of the data, at low resolution. Low
fidelity is noisy but cheap; high fidelity is accurate but expensive. The bet is
that **relative ranking is roughly preserved across fidelities**: a configuration
that is much worse after a little training is unlikely to become the best after
a lot<FN n="1" />. It is only roughly true, which is why you promote *several* survivors rather
than committing to the single leader early.

## Successive halving

Successive halving (SHA) organizes the search into **rungs**. Pick a reduction
factor $\eta$ (typically $3$). Start with $n$ configurations at the smallest
budget $b$, then repeat:

- **Step 1.** Evaluate every surviving configuration at the current budget.
- **Step 2.** Keep the top $1/\eta$ of them by score; discard the rest.
- **Step 3.** Multiply the budget by $\eta$ and go to step 1, until one
  configuration remains.

So the counts shrink as $n, n/\eta, n/\eta^2, \dots$ while the per-configuration
budget grows as $b, b\eta, b\eta^2, \dots$. The two cancel: at every rung the total
work spent is

$$
n_r \cdot b_r = \frac{n}{\eta^{r}} \cdot b\,\eta^{r} = n\,b,
$$

a **constant** independent of the rung $r$. The whole sweep therefore costs about
$n b (R+1)$ for $R+1$ rungs, instead of the $n \cdot b_{\max}$ it would cost to
train all $n$ configurations to the full budget $b_{\max} = b\,\eta^{R}$. With
$\eta=3$ and four rungs that is a budget reduction of roughly $b_{\max}/(b(R+1)) =
27/4$, almost $7\times$, and the saving grows with the number of rungs.

The price is the assumption from above: a late-blooming configuration that looks
mediocre early can be cut before it would have shone. **Hyperband** hedges this by
running several SHA brackets with different starting trade-offs (many configs cut
aggressively, vs. fewer configs given more budget each), and **ASHA** makes the
whole thing asynchronous so idle workers promote survivors without waiting for a
rung to finish, which is what scales it to a real cluster<FN n="2" />.

## Worked example

We run successive halving with $n=27$, $\eta=3$, starting budget $1$. Each
configuration has a hidden true quality; a low-budget evaluation is a noisy proxy
for it whose noise shrinks as the budget grows.

```python
import numpy as np
rng = np.random.default_rng(1)

n, eta, b0 = 27, 3, 1
true_quality = rng.uniform(0, 1, size=n)        # hidden final score per config
def evaluate(ids, budget):                       # noisy proxy; noise ~ 1/sqrt(budget)
    noise = rng.normal(0, 0.05 / np.sqrt(budget), size=ids.size)
    return true_quality[ids] + noise

R = int(round(np.log(n) / np.log(eta)))          # number of cuts: rungs 0..R (here 3)
alive = np.arange(n)
total = 0
for r in range(R + 1):
    budget = b0 * eta ** r                       # per-config budget grows by eta
    scores = evaluate(alive, budget)
    total += alive.size * budget                 # work this rung = n_r * b_r (constant)
    print(f"rung {r}: {alive.size:2d} configs @ budget {budget:2d}  "
          f"-> rung cost {alive.size * budget}")
    if alive.size > 1:
        keep = max(1, alive.size // eta)
        alive = alive[np.argsort(scores)[::-1][:keep]]   # top 1/eta survive

survivor = alive[0]
b_max = b0 * eta ** R                             # full budget = 27
full_cost = n * b_max                             # train all n to full budget
survivor_rank = 1 + int(np.sum(true_quality > true_quality[survivor]))
print(f"survivor config {survivor}, true rank {survivor_rank} of {n}")
print(f"SHA total budget {total}  vs  full-budget-for-all {full_cost}")
assert survivor_rank <= 3        # lands among the very best (not guaranteed THE best)
assert total < full_cost
print(f"speedup over training all to convergence: {full_cost / total:.2f}x")
```

Each rung costs the same $27$ units of budget, the survivor lands among the very
best configurations (here, the top-ranked one, though that is not guaranteed, which
is exactly why several survivors are promoted per rung), and the sweep spends a
small fraction of what training all $27$ configurations to convergence would.

## Exercises

**Exercise 1.** Run successive halving by hand with $n = 81$ configurations,
reduction factor $\eta = 3$, and starting budget $b = 1$. List the
(count, per-config budget) pair at each rung, confirm that the per-rung work is
constant, and compute the total budget. Then compute the budget that training all
$81$ configurations to the full budget $b_{\max}$ would cost, and give the
speedup.

<details>
<summary>Solution</summary>

**Step 1.** Counts shrink by $\eta = 3$ and budgets grow by $\eta$ each rung,
starting from $(81, 1)$ until one survivor remains:

- Rung 0: $(81, 1)$, work $81 \cdot 1 = 81$.
- Rung 1: $(27, 3)$, work $27 \cdot 3 = 81$.
- Rung 2: $(9, 9)$, work $9 \cdot 9 = 81$.
- Rung 3: $(3, 27)$, work $3 \cdot 27 = 81$.
- Rung 4: $(1, 81)$, work $1 \cdot 81 = 81$.

**Step 2.** Every rung does $n_r b_r = (n/\eta^r)(b\eta^r) = nb = 81$ units, the
promised constant. There are $R + 1 = 5$ rungs (since
$R = \log_3 81 = 4$), so the total is $81 \cdot 5 = 405$ units.

**Step 3.** Training all $81$ to the full budget $b_{\max} = b\,\eta^R = 81$ costs
$81 \cdot 81 = 6561$ units. The speedup is $6561 / 405 = 16.2\times$.

</details>

**Exercise 2.** The whole scheme rests on relative ranking being roughly preserved
across fidelities. Suppose at the first rung a configuration's low-budget score is
its true quality plus zero-mean noise of standard deviation $\sigma_b$, and noise
shrinks as $\sigma_b = c/\sqrt{b}$. Argue qualitatively why raising the starting
budget $b$ lowers the chance of cutting a truly good configuration, and why that
gain trades against the number of configurations you can afford to start.

<details>
<summary>Solution</summary>

**Step 1.** A good configuration is wrongly cut when noise pushes its observed
score below the survival cutoff. Larger noise $\sigma_b$ widens the spread of
observed scores around the true ordering, so more good configurations land below
the cutoff by chance.

**Step 2.** Since $\sigma_b = c/\sqrt{b}$, raising the starting budget $b$ shrinks
$\sigma_b$, tightening observed scores around true quality and making the
top-$1/\eta$ cut at rung 0 closer to a true-quality cut. The mis-cut probability
falls.

**Step 3.** Total budget is finite. For fixed total $\approx n b (R+1)$, raising
$b$ forces $n$ down, so fewer configurations are explored at the start. Cleaner
early ranking is bought with a narrower search. Hyperband resolves the dilemma by
running several brackets at different $(n, b)$ trade-offs rather than committing to
one.

</details>

**Exercise 3 (code).** Implement successive halving for general $(n, \eta, b)$
with $n$ a power of $\eta$. Assert that the per-rung work is exactly $nb$ at every
rung, that the number of rungs is $\log_\eta n + 1$, and that the total budget
matches $nb(R+1)$. Run it for $(n, \eta) = (81, 3)$ and report the speedup over
full training.

<details>
<summary>Solution</summary>

```python
import numpy as np

def sha_budget(n, eta, b=1):
    R = round(np.log(n) / np.log(eta))      # number of cuts
    rung_work, counts = [], []
    count, budget = n, b
    for r in range(R + 1):
        rung_work.append(count * budget)
        counts.append((count, budget))
        count //= eta
        budget *= eta
    return R, rung_work, counts

n, eta, b = 81, 3, 1
R, rung_work, counts = sha_budget(n, eta, b)

# Every rung does exactly n*b units of work.
assert all(w == n * b for w in rung_work)
# Number of rungs is log_eta(n) + 1.
assert R + 1 == round(np.log(n) / np.log(eta)) + 1 == 5
# Total budget equals n*b*(R+1).
total = sum(rung_work)
assert total == n * b * (R + 1) == 405

b_max = b * eta ** R                         # full budget = 81
full_cost = n * b_max                        # train all n to full budget
speedup = full_cost / total
assert np.isclose(speedup, 6561 / 405)
print("counts/budgets per rung:", counts)
print(f"SHA total {total} vs full {full_cost}, speedup {speedup:.2f}x")
```

The per-rung work is a flat $81$ units, the five rungs total $405$, and the sweep
runs $16.2\times$ cheaper than training all $81$ configurations to convergence,
matching the hand computation.

</details>
