Hyperparameters (learning rate, weight decay, layer width, dropout) are the knobs
you set *before* training, and a model's quality can swing wildly with them.
Tuning them is **black-box optimization**: you cannot differentiate "final
validation accuracy" with respect to the learning rate, you can only pick a
configuration, pay for a full training run, and read off the score. With each
evaluation this expensive, the question is how to spend a fixed budget of $N$ runs
to find a good configuration. The surprising answer is that the obvious method,
grid search, is usually the wrong one.

## Grid search and its blind spot

**Grid search** picks a finite set of values per hyperparameter and evaluates
every combination. With $d$ hyperparameters and $k$ values each, that is $k^d$
runs: the budget explodes with the number of knobs (the **curse of
dimensionality**), so in practice $k$ is forced small, often $3$ or $4$.

The blind spot is what a grid does *per axis*. Lay out a $3 \times 3$ grid over
two hyperparameters and project onto either axis: the nine points only ever use
**three** distinct values of each hyperparameter, because the other axis's
variation is wasted from that hyperparameter's point of view. So a budget of nine
runs explores each knob at a resolution of three. If one knob barely affects the
score and the other is decisive, grid search has spent most of its nine runs
re-checking the decisive knob at the *same* three settings while varying the knob
that does not matter.

## Why random search wins

Real hyperparameter landscapes have **low effective dimensionality**: out of many
knobs, only a few strongly move the score. Bergstra and Bengio's 2012 result
follows directly<FN n="1" />. **Random search** draws each of the $N$ configurations
independently and uniformly from the search space. Project those $N$ points onto
any single axis and you get $N$ *distinct* values of that hyperparameter, not
$\sqrt{N}$ as a square grid gives, not $N^{1/d}$ as a $d$-dimensional grid gives.

So for the few hyperparameters that actually matter, random search tries $N$
different settings while a grid tries only $N^{1/d}$. The same budget buys far
finer coverage of the dimensions that count, because random search never wastes
resolution coordinating values across axes. The more irrelevant knobs there are,
the bigger the gap, which is why random search is the standard baseline and the
starting point for the smarter [Bayesian methods](A/bayesian-optimization) and
bandit-based schedulers that spend the budget adaptively<FN n="2" />.

## Worked example

The objective depends almost entirely on one hyperparameter and ignores the other.
With a budget of nine evaluations, we compare a $3 \times 3$ grid against random
search, averaged over many random draws.

```python
import numpy as np

# Score depends on dim 0 (peak at 0.3); dim 1 is nearly irrelevant.
def score(x0, x1):
    return -(x0 - 0.3) ** 2 - 0.01 * (x1 - 0.7) ** 2

budget = 9

# Grid search: 3x3 -> only 3 distinct values of the important hyperparameter x0.
g = np.linspace(0.05, 0.95, 3)
grid_best = max(score(a, b) for a in g for b in g)
grid_distinct_x0 = len(set(np.round(a, 6) for a in g for b in g))

# Random search: 9 draws -> 9 distinct x0 values. Average over many random seeds.
rng = np.random.default_rng(0)
rand_bests, rand_distinct = [], []
for _ in range(2000):
    xs = rng.uniform(0, 1, size=(budget, 2))
    rand_bests.append(max(score(a, b) for a, b in xs))
    rand_distinct.append(len({round(a, 6) for a, _ in xs}))

print(f"grid:   {grid_distinct_x0} distinct x0 values, best score {grid_best:.4f}")
print(f"random: {np.mean(rand_distinct):.0f} distinct x0 values, "
      f"mean best score {np.mean(rand_bests):.4f}")
assert np.mean(rand_bests) > grid_best        # random wins on the same budget
print("random search beats grid on the same budget:", True)
```

With nine runs the grid pins the important hyperparameter to three coarse values
and never gets close to the peak at $0.3$, while random search, sampling nine
distinct values of it, lands nearer on average.

## Exercises

**Exercise 1.** You have a budget of $N = 64$ runs over $d$ hyperparameters using
a balanced grid (the same number $k$ of values per axis, so $N = k^d$). Compute
the per-axis resolution $k$ for $d = 1, 2, 3, 6$. Contrast each with the per-axis
resolution random search achieves on the same budget, and state in one sentence
what the table says about where grid search fails.

<details>
<summary>Solution</summary>

**Step 1.** A balanced grid spends $N = k^d$, so $k = N^{1/d}$. With $N = 64$:

- $d = 1$: $k = 64^{1} = 64$.
- $d = 2$: $k = 64^{1/2} = 8$.
- $d = 3$: $k = 64^{1/3} = 4$.
- $d = 6$: $k = 64^{1/6} = 2$.

**Step 2.** Random search draws each of the $64$ configurations independently, so
projecting onto any single axis gives $64$ distinct values of that hyperparameter
regardless of $d$.

**Step 3.** Grid resolution per axis collapses as $N^{1/d}$ while random search
holds at $N$. As the number of knobs grows, the grid checks each important
hyperparameter at fewer and fewer settings ($2$ values at $d = 6$), which is
exactly where it fails: with several knobs, the grid cannot resolve the few that
matter.

</details>

**Exercise 2.** Suppose only one of $d$ hyperparameters affects the score, and a
configuration counts as a "hit" if its value of that one knob lands in the best
fraction $f$ of its range. For random search, the probability that **none** of
$N$ independent draws is a hit is $(1 - f)^N$. Find the smallest $N$ that drives
the miss probability below $0.05$ for $f = 0.05$, and explain why this bound does
not depend on $d$.

<details>
<summary>Solution</summary>

**Step 1.** Require $(1 - f)^N \le 0.05$ with $f = 0.05$, i.e.
$0.95^N \le 0.05$.

**Step 2.** Take logs: $N \ln 0.95 \le \ln 0.05$. Both logs are negative, so
dividing flips the inequality:

$$
N \ge \frac{\ln 0.05}{\ln 0.95} = \frac{-2.996}{-0.0513} \approx 58.4,
$$

so $N = 59$ runs.

**Step 3.** Each draw is uniform over the whole space, so its projection onto the
one relevant axis is uniform on that axis whatever the other $d - 1$ knobs do.
The hit probability $f$ per draw, and therefore the miss bound $(1-f)^N$, is set
entirely by the relevant axis; the irrelevant dimensions never enter. Random
search is insensitive to how many useless knobs are bolted on.

</details>

**Exercise 3 (code).** Confirm the projection fact and the coverage gap directly.
For a $d$-dimensional balanced grid and random search on the same budget $N$,
count the distinct values each method produces along a single axis, and check
that the random count matches $N$ while the grid count matches $N^{1/d}$.

<details>
<summary>Solution</summary>

```python
import numpy as np
rng = np.random.default_rng(0)

def grid_distinct_per_axis(N, d):
    k = round(N ** (1 / d))                 # values per axis on a balanced grid
    axis = np.linspace(0, 1, k)
    pts = np.array(np.meshgrid(*([axis] * d))).reshape(d, -1).T
    return len(np.unique(np.round(pts[:, 0], 9))), k

def random_distinct_per_axis(N, d):
    pts = rng.uniform(0, 1, size=(N, d))
    return len(np.unique(np.round(pts[:, 0], 9)))

N = 64
for d in [2, 3, 6]:
    g, k = grid_distinct_per_axis(N, d)
    r = random_distinct_per_axis(N, d)
    assert g == k == round(N ** (1 / d))    # grid: N^(1/d) distinct per axis
    assert r == N                            # random: N distinct per axis
    print(f"d={d}: grid {g} distinct/axis, random {r} distinct/axis")
```

The grid resolves each axis at only $N^{1/d}$ values, which shrinks fast as $d$
grows, while random search resolves it at the full $N$ on every axis, which is the
coverage advantage the lesson's argument rests on.

</details>
